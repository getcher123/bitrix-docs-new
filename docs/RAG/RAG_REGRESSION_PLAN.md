# План регресс‑тестов RAG

Цель — убедиться, что качество поиска и ссылок не деградирует после обновлений.

## Набор регресс‑проверок

1) Контрольные вопросы: `docs/RAG/RAG_TEST_SET.md`  
2) Отчет метрик: `docs/RAG/RAG_EVAL_REPORT.csv`  
3) Временные метрики: `docs/RAG/RAG_TEST_REPORT_TIMINGS.csv` (если актуален)

## Запуск

```bash
python3 rag/scripts/eval_test_set.py --env-file rag/.env --top-k 10 --out docs/RAG/RAG_EVAL_REPORT.csv
```

## Критерии

- Recall@10 ≥ 0.85
- MRR@10 ≥ 0.70
- В каждом ответе 2–4 локальные ссылки на `docs/...`
- Нет внешних `http(s)` ссылок в теле ответа

## Что фиксировать

- дату запуска и версию индекса (`.rag/index_version.json`),
- медиану времени ответа и p95 (если снимается),
- список вопросов, где нет попаданий.
